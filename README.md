# Sungold Store — قالب بازار ۴٫۸ + اپ مدیریت ۲٫۵

دو بخش در یک مخزن:

| پوشه | چیست |
|---|---|
| `theme/bazar` | قالب وردپرس/ووکامرس (راست‌چین، موبایل‌اول) با **API تنظیمات** و پیش‌نمایش زنده |
| `app` | **وب‌اپ قابل نصب (PWA)** برای کنترل ظاهر قالب، بنرها، **محصولات و سئوی محصولات** از روی گوشی |
| `tools` | سرور آزمایشی (بدون وردپرس)، تست‌ها و چک‌کننده‌ی PHP |
| `capacitor.config.json`، `assets/` | بسته‌بندی اپ به‌صورت APK اندروید (workflow: `android.yml`) |

## راه‌اندازی (۵ قدم)

1. **قالب:** فایل `bazar-theme.zip` را از بخش *Actions → آخرین اجرا → Artifacts* بردارید و در وردپرس نصب و فعال کنید.
   (یا پوشه‌ی `theme/bazar` را به‌صورت zip کنید.)
2. **فونت:** فایل `Vazirmatn-Variable.woff2` را در `theme/bazar/assets/fonts/` و `app/fonts/` بگذارید.
3. **اپ:** در GitHub: *Settings → Pages → Source: GitHub Actions*. بعد از اولین push روی `main`، اپ در `https://<user>.github.io/<repo>/` منتشر می‌شود.
4. **رمز برنامه:** پیشخوان وردپرس ← کاربران ← پروفایل ← «رمزهای عبور برنامه» ← نام `Sungold App` ← افزودن ← رمز را کپی کنید.
5. **اتصال:** اپ را باز کنید، آدرس سایت + نام کاربری + رمز برنامه را وارد کنید. روی گوشی «افزودن به صفحه‌ی اصلی» بزنید.

> سایت باید **HTTPS** داشته باشد (Application Passwords روی HTTP کار نمی‌کند).

## چه چیزی از اپ قابل کنترل است؟

همه‌چیز از `theme/bazar/inc/schema.json` ساخته می‌شود؛ **تنها منبع حقیقت** برای قالب، API و فرم‌های اپ. فیلد جدید = یک آبجکت در همین فایل.

| بخش | تنظیمات |
|---|---|
| هویت | نام فروشگاه، شعار، لوگو، آیکن سایت |
| رنگ و ظاهر | ۵ پالت آماده، ۴ رنگ (اصلی/تأکید/متن/تخفیف)، گردی گوشه‌ها. بقیه‌ی رنگ‌ها **خودکار** با تضمین خوانایی ساخته می‌شوند |
| هدر و فوتر | نوار بالا، ناوبری پایین موبایل، تلفن/واتس‌اپ/اینستاگرام/تلگرام/ایمیل، متن فوتر و کپی‌رایت |
| صفحه اصلی | **ترتیب و روشن/خاموش‌کردن بخش‌ها**، هیرو (متن، دکمه‌ها، حالت رنگی)، محصولات ویژه، بنر تخفیف، مزایا |
| فروشگاه | تعداد محصول در صفحه، ستون‌ها، نوار افزودن به سبد |

همین تنظیمات در **سفارشی‌سازی وردپرس** هم هست و در همان گزینه (`bazar_settings`) ذخیره می‌شود؛ اپ و پیشخوان همیشه هماهنگ‌اند.

## بنرها، محصولات و سئوی محصول (نسخه‌ی ۲ اپ / قالب ۴.۵)

اپ چهار تب دارد: **ظاهر** (تنظیمات قالب)، **بنرها** (میان‌بر مستقیم به ویرایشگر بنر اسلایدر)، **محصولات** و **سفارشات**.

**بنرها** — حداکثر ۸ بنر؛ هر کدام تصویر (کوچک‌سازی خودکار قبل از آپلود)، لینک، متن جایگزین (alt)، روشن/خاموش و ترتیب. اندازه‌ی پیشنهادی ۱۶۰۰×۹۰۰. با ذخیره، اسلایدر صفحه‌ی اصلی جای متن هیرو را می‌گیرد.

**محصولات** — فهرست با جست‌وجو، فیلتر منتشرشده/پیش‌نویس و صفحه‌بندی؛ ساخت و ویرایش محصول ساده: نام، نامک، توضیح کوتاه و کامل، قیمت و قیمت با تخفیف (ارقام فارسی و جداکننده‌ی هزارگان پذیرفته می‌شود)، SKU، موجودی (تعداد یا وضعیت)، دسته‌ها، تصویر اصلی، گالری و alt هر تصویر. حذف = انتقال به زباله‌دان (قابل بازیابی). محصولات متغیر: همه‌چیز جز قیمت قابل ویرایش است.

**سئوی هر محصول** — عنوان سئو، توضیح متا، کلمه‌ی کلیدی اصلی، نامک و noindex، با:
- پیش‌نمایش زنده‌ی نتیجه‌ی گوگل و شمارنده‌ی کاراکتر؛
- **امتیاز ۰ تا ۱۰۰** و فهرست بررسی (طول عنوان/متا، وجود کلمه‌ی کلیدی در عنوان/متا/نامک/ابتدای توضیحات، طول توضیحات، تصویر و alt)؛ تطبیق کلمه‌ی کلیدی با ی/ک عربی، نیم‌فاصله و ارقام فارسی سازگار است؛
- **سئوی خودکار (قاعده‌ای، رایگان، آفلاین؛ بدون هوش مصنوعی):** از اسم و توضیحات محصول، کلمه‌ی کلیدی (۲ کلمه‌ی اول؛ ۳ کلمه برای اسم کوتاه؛ تا «مدل/سری/کد»)، عنوان ۳۰–۶۰ کاراکتر («خرید آنلاین … | نام فروشگاه»)، توضیح متا ۱۲۰–۱۶۰ کاراکتر (از جمله‌های توضیح کوتاه/کامل)، نامک و alt یکتای تصاویر می‌سازد.
  - **هنگام ذخیره** خودش فقط موارد **خالی** را پر می‌کند (کلید «پر کردن خودکار سئو هنگام ذخیره»؛ پیش‌فرض روشن)؛ آنچه خودتان نوشته‌اید هرگز عوض نمی‌شود.
  - دکمه‌ی **«پر کردن خودکار سئو»** (فقط موارد خالی) و **«ساخت دوباره‌ی همه»**؛ و در فهرست، **«تکمیل خودکار سئوی محصولات ناقص»** که برای همه‌ی محصولات بدون عنوان/توضیح متا اجرا می‌شود و **نشانی (نامک) محصولات موجود را عوض نمی‌کند**.

**کجا ذخیره می‌شود؟** اگر Rank Math یا Yoast SEO فعال باشد، همان‌جا (عنوان، توضیح، کلمه‌ی کلیدی). در غیر این‌صورت سئوی داخلی قالب: `<title>`، متا، Open Graph و noindex (`wp_robots`) خروجی می‌گیرد. اگر افزونه‌ی سئوی دیگری (AIOSEO، SEOPress، …) فعال باشد، فیلدهای متا غیرفعال می‌شوند و فقط تحلیل و نامک/alt قابل ویرایش است.

| مسیر (`/wp-json/bazar/v1`) | دسترسی | کار |
|---|---|---|
| `GET /products/meta` | `edit_products` | دسته‌ها، نوع ذخیره‌ی سئو، واحد پول |
| `GET /products` | `edit_products` | فهرست؛ `search`، `status=publish\|draft`، `category`، `page` (۲۰ تا در هر صفحه) |
| `POST /products` | `publish_products` | ساخت محصول ساده (پیش‌فرض پیش‌نویس) |
| `GET /products/{id}` | `edit_post` | جزئیات کامل |
| `POST /products/{id}` | `edit_post` | ویرایش جزئی (`PUT`/`PATCH` هم) |
| `DELETE /products/{id}` | `delete_post` | انتقال به زباله‌دان |

ورودی‌ها در سرور پاک‌سازی می‌شوند (`wp_kses_post` برای توضیحات، اعتبارسنجی قیمت، SKU یکتا، فقط تصویرهای واقعی کتابخانه‌ی رسانه، حداکثر ۱۲ تصویر گالری). تنظیمات ظاهر همچنان فقط با `manage_options` است؛ مدیر هر دو را دارد.

محدودیت‌ها: ساخت/ویرایش ویژگی‌ها و تنوع‌ها (variations)، ویرایش گروهی و کوپن‌ها هنوز در اپ نیست. (سفارش‌ها از نسخه‌ی ۲٫۴ اپ هست؛ بخش بعد.)

## سفارشات (نسخه‌ی ۲٫۴ اپ / قالب ۴٫۷)

تب **سفارشات** (چهارمین تب). همه‌چیز با CRUD خود ووکامرس (`wc_get_orders`/`wc_get_order`) انجام می‌شود؛ پس با **HPOS** و ذخیره‌ی قدیمی هر دو سازگار است. دسترسی: توانایی `edit_shop_orders` (مدیر و مدیر فروشگاه).

- **فهرست:** جدیدترین اول، ۲۰ تا در هر صفحه، فیلتر وضعیت با شمار هر وضعیت، جستجو با شماره‌ی سفارش (ارقام فارسی هم) یا نام/تلفن/محصول، **آمار امروز / ۷ روز / ۳۰ روز** (تعداد و فروش خالص بدون مسترد‌شده‌ها؛ سفارش‌های در حال انجام، تکمیل‌شده و در انتظار بررسی).
- **جزئیات:** اقلام با ویژگی‌های تنوع و SKU، جمع‌ها (تخفیف، ارسال، مالیات، هزینه‌ها)، روش و وضعیت پرداخت، آدرس ارسال با دکمه‌ی کپی، **تماس و واتس‌اپ با یک لمس** (شماره‌ی ۰۹… خودکار به فرمت بین‌المللی می‌رود)، یادداشت مشتری، تاریخ شمسی.
- **تغییر وضعیت** با یادداشت اختیاری؛ همان رفتار پیشخوان (ایمیل‌ها و اصلاح موجودی). **استرداد وجه عمداً از اپ ممکن نیست** (باید رکورد استرداد ساخته شود؛ سرور هم رد می‌کند).
- **کد رهگیری:** ذخیره، با گزینه‌ی اطلاع‌رسانی به مشتری (یادداشت مشتری ← ایمیل)؛ در صفحه‌ی سفارش مشتری و ایمیل‌های او هم نمایش داده می‌شود.
- **یادداشت‌ها:** خصوصی یا برای مشتری (با تأیید قبل از ارسال ایمیل).
- **سفارش تازه:** هر ۶۰ ثانیه (فقط وقتی اپ باز و دیده می‌شود) شناسه‌ی تازه‌ترین سفارش و تعداد «در حال انجام + درخواست خرید» خوانده می‌شود؛ شمارنده‌ی قرمز روی تب و پیام «سفارش/درخواست خرید جدید رسید» (از ۲٫۵ با شناسه‌ی سفارش، نه مقایسه‌ی تعداد). **این اعلان لحظه‌ای (Push) نیست؛ وقتی اپ بسته است چیزی نمی‌رسد.** Push واقعی نیاز به Firebase (FCM) و ساخت APK با افزونه‌ی اعلان دارد.

| مسیر (`/wp-json/bazar/v1`) | کار |
|---|---|
| `GET /orders/meta` | وضعیت‌ها، شمار هر وضعیت، واحد پول |
| `GET /orders/stats` | تعداد و فروش امروز / ۷ / ۳۰ روز |
| `GET /orders` | فهرست؛ `status`، `search`، `from`/`to` (`YYYY-MM-DD`)، `page` |
| `GET /orders/{id}` | جزئیات کامل |
| `POST /orders/{id}` | `{status, note}` و/یا `{tracking, notify_tracking}` |
| `POST /orders/{id}/notes` | `{note, customer}` |

محدودیت‌ها: ساخت سفارش دستی، ویرایش اقلام/آدرس، استرداد وجه، چاپ فاکتور و ارسال گروهی هنوز در اپ نیست. آمار ۳۰ روزه بر پایه‌ی حداکثر ۱۵۰۰ سفارش آخر است (روی فروشگاه‌های خیلی پرسفارش ممکن است کم‌شمار شود؛ اپ هشدار می‌دهد). **`inc/orders.php` هم مثل `products.php` هنوز روی وردپرس و ووکامرس واقعی اجرا نشده**؛ روی staging با `WP_DEBUG=true` امتحان کنید.

## درخواست خرید قبل از پرداخت (نسخه‌ی ۲٫۵ اپ / قالب ۴٫۸)

برای اینکه فروشنده قبل از پرداخت، موجودی را چک کند. **پیش‌فرض خاموش است**؛ از «ظاهر ← فروشگاه ← درخواست خرید قبل از پرداخت» (یا Customizer) روشن می‌شود.

**جریان:**
1. مشتری سبد را می‌بندد؛ در صفحه‌ی پرداخت فقط روش **«ثبت درخواست خرید»** را می‌بیند (درگاه‌های بانکی پنهان می‌شوند). هیچ پرداختی انجام نمی‌شود؛ سفارش با وضعیت تازه‌ی **«درخواست خرید»** ثبت می‌شود و به مدیر ایمیل می‌رسد. مشتری نمی‌تواند پرداخت کند (صفحه‌ی پرداخت ووکامرس فقط برای «در انتظار پرداخت» کار می‌کند).
2. در اپ (تب سفارشات؛ شمارنده‌ی روی تب شامل درخواست‌هاست) درخواست را باز می‌کنید: برای **هر قلم** تعداد درخواستی در برابر موجودی فعلی و «کافی / ناکافی» نشان داده می‌شود.
3. **تأیید:** موجودی برای مشتری **رزرو** می‌شود، وضعیت «در انتظار پرداخت» می‌شود و پیوند پرداخت (با مهلت، پیش‌فرض ۲۴ ساعت؛ قابل تغییر در همان کارت) به‌صورت یادداشت/ایمیل مشتری می‌رود. اگر موجودی کافی نباشد، سرور بدون `force` رد می‌کند و اپ فقط با تأیید صریح شما ادامه می‌دهد.
4. **رد:** سفارش لغو می‌شود و دلیل برای مشتری ایمیل می‌شود.
5. اگر مشتری تا پایان مهلت پرداخت نکند، یک کار زمان‌بندی‌شده‌ی ساعتی سفارش را لغو و موجودی را آزاد می‌کند. (تنظیم «نگهداری موجودی» ووکامرس روی این سفارش‌ها اثر ندارد.)

| مسیر (`/wp-json/bazar/v1`) | کار |
|---|---|
| `POST /orders/{id}/approve` | `{hours?, note?, force?}` — خطای `409 bazar_stock_short` (با فهرست اقلام) یا `409 bazar_not_request` |
| `POST /orders/{id}/reject` | `{reason?}` |
| `GET /orders/{id}` | حالا بخش `request` دارد (`awaiting` با فهرست موجودی، یا `approved` با زمان انقضا) |
| `GET /orders/meta` | `latest_id` و `request_mode` اضافه شد |

**قفل‌ها:** وضعیت «درخواست خرید» با تغییر وضعیت عادی (API) عوض نمی‌شود؛ فقط تأیید/رد. دستی‌ساختن این وضعیت هم رد می‌شود.

**چک‌اوت کلاسیک و بلوکی:** روش پرداخت هر دو را پشتیبانی می‌کند (`inc/request-gateway.php` و `inc/request-blocks.php` + `assets/request-blocks.js`). **هیچ‌کدام روی ووکامرس واقعی اجرا نشده.** اگر روش «ثبت درخواست خرید» به هر دلیل در دسترس نباشد، فهرست درگاه‌ها دست‌نخورده می‌ماند تا فروشگاه از کار نیفتد؛ پس بعد از روشن‌کردن حتماً با یک خرید آزمایشی تأیید کنید که درگاه‌های بانکی دیگر نشان داده نمی‌شوند.

**چک تست روی staging:** (۱) روشن‌کردن؛ (۲) خرید به‌عنوان مهمان و به‌عنوان کاربر؛ (۳) تأیید ← کاهش موجودی محصول؛ (۴) باز کردن پیوند پرداخت و پرداخت با درگاه آزمایشی ← وضعیت «در حال انجام» و بدون کسر دوباره‌ی موجودی؛ (۵) رد؛ (۶) انقضا (مهلت ۱ ساعت و اجرای `wp cron event run bazar_req_expire`).

## استودیوی عکس (نسخه‌ی ۲٫۲ اپ)

داخل فرم محصول، بخش «تصاویر»: دکمه‌ی **«آماده‌سازی عکس خام»** (برای تصویر اصلی) و **«افزودن عکس خام»** (برای گالری). عکس را از گالری یا دوربین انتخاب می‌کنید و استودیو باز می‌شود:

- **حذف پس‌زمینه** — **«با کادر» (پیش‌فرض)**: دور محصول با انگشت یک کادر می‌کشید و الگوریتم GrabCut (پیاده‌سازی خودمان، کاملاً آفلاین) محصول را از هر پس‌زمینه‌ای، حتی شلوغ، جدا می‌کند؛ نوشته‌های تیره‌ی داخل محصول حفظ می‌شود و سوراخ‌هایی مثل دسته‌ی جعبه با یک لمس باز/بسته می‌شود. «ساده» (فقط برای عکس روی دیوار/میز/کاغذ یک‌رنگ؛ حساسیت قابل تنظیم و چکاننده‌ی رنگ پس‌زمینه)، «هوشمند» (آزمایشی؛ مدل متن‌باز `@imgly/background-removal` روی خود گوشی، برای پس‌زمینه‌ی شلوغ) یا «بدون حذف».
- **برش و چیدمان** — محصول خودکار وسط بوم می‌آید؛ نسبت مربع / ۴:۵ / اصلی، حاشیه‌ی قابل تنظیم.
- **پس‌زمینه‌ی جدید** — سفید، خاکستری، رنگ دلخواه یا شفاف؛ سایه‌ی نرم زیر محصول.
- **خروجی** — ۸۰۰/۱۲۰۰/۱۶۰۰ پیکسل، WebP (سبک برای سایت). «ذخیره در گوشی» یا «استفاده برای محصول» (آپلود خودکار و پر شدن alt با نام محصول).

حذف «ساده» کاملاً آفلاین است و تصویر هرگز از گوشی بیرون نمی‌رود. «هوشمند» در یک iframe ایزوله (`sandbox="allow-scripts"`، بدون دسترسی به رمز و تنظیمات اپ) اجرا می‌شود و فقط خودِ عکس را رد و بدل می‌کند؛ کتابخانه از `cdn.jsdelivr.net` و مدل از `staticimgly.com` دانلود می‌شود (آدرس و نسخه در `app/studio-ai.html`). **این بخش با موتور واقعی هنوز آزمایش نشده؛** پل ارتباطی و ایزوله‌سازی با موتور شبیه‌سازی‌شده تست شده است. اگر نسخه یا آدرس تغییر کرده باشد، خطای دوستانه می‌دهد و روش «ساده» در دسترس می‌ماند.

**درستی GrabCut:** جریان بیشینه (Boykov–Kolmogorov) با Edmonds–Karp روی ۲۱۰ گراف تصادفی برابر است (`tools/test-maxflow.mjs`)؛ خروجی روی یک صحنه‌ی ساختگی دقیقاً با `cv2.grabCut` یکی است (IoU = ۱٫۰۰۰) و روی یک عکس واقعی قفسه‌ی فروشگاه ۰٫۹۷۷. اجرا روی عکس ۴۸۰ پیکسلی حدود ۱ ثانیه (در Node).

محدودیت‌ها: GrabCut هم مثل هر روش کادری وقتی بخشی از پس‌زمینه‌ی داخل کادر هم‌رنگ محصول باشد اشتباه می‌کند؛ کادر را نزدیک محصول بکشید. قلم اصلاح (علامت‌زدن دستی پیش‌زمینه/پس‌زمینه) هنوز نیست. روش «ساده» برای محصول هم‌رنگ پس‌زمینه (مثلاً لباس سفید روی دیوار سفید) و سایه‌های پررنگ کار نمی‌کند؛ عکس‌های HEIC (برخی آیفون‌ها) را مرورگر اندروید باز نمی‌کند؛ پردازش دسته‌ای (چند عکس هم‌زمان) هنوز نیست.

## ظاهر مدرن (قالب ۴٫۶)

لایه‌ی جدید انتهای `style.css` (بخش «۴٫۶ لایه‌ی مدرن») بدون تغییر در ساختار صفحه یا تنظیمات قبلی، ظاهر را بالا می‌برد:
- **قهرمان:** درخشش نرم و بافت نقطه‌ای، تیتر درشت‌تر، دکمه‌ها با فلش و حرکت ورود کمان‌ها؛ کاشی‌ها با نقش کمان و واکنش لمسی.
- **ریتم و عمق:** سایه‌های دولایه، فاصله‌ی منظم بین بخش‌ها، تیتر بخش‌ها با نشان کمان، فوتر گرد با درخشش.
- **کارت محصول:** بدون حاشیه‌ی سنگین، سایه و بالا‌رفتن هنگام لمس، قیمت درشت با «تومان» کم‌رنگ و دکمه‌ی سبد خرید گرد روی تصویر (نمای آیکنی؛ متن دکمه برای صفحه‌خوان‌ها می‌ماند).
- **همه‌ی رنگ‌بندی‌ها:** فقط از متغیرهای رنگ استفاده می‌شود، پس با پالت‌های آماده‌ی اپ (مشکی و طلایی، عنابی و رزگلد، …) سازگار است.

دو گزینه‌ی تازه در اپ، تب «ظاهر ← رنگ و ظاهر ← فونت و جلوه‌ها»:
- **جلوه‌ها و انیمیشن‌های مدرن** (پیش‌فرض روشن): ظهور نرم بخش‌های پایین صفحه، حرکت قهرمان. برای گوشی‌های ضعیف خاموش کنید. با `prefers-reduced-motion` خودکار خاموش می‌شود.
- **بارگذاری فونت از گوگل** (پیش‌فرض روشن): پوشه‌ی `assets/fonts` خالی است و بدون آن سایت با فونت پیش‌فرض دستگاه دیده می‌شود. اگر فایل‌های `Vazirmatn-Variable.woff2` و `Lalezar-Regular.woff2` را آن‌جا گذاشتید، این گزینه را خاموش کنید.

**تست‌شده:** نمای صفحه‌ی اول با CSS واقعی قالب روی سرور آزمایشی، دسکتاپ و موبایل و دو پالت. **تست نشده:** صفحه‌ی محصول، سبد، پرداخت و آرشیو فروشگاه با وردپرس و ووکامرس واقعی؛ و نمایش فونت‌های گوگل در ایران.

## API (`/wp-json/bazar/v1`)

| مسیر | دسترسی | کار |
|---|---|---|
| `GET /ping` | عمومی | نام سایت/نسخه؛ برای تست اتصال |
| `GET /schema` | مدیر | تعریف فرم‌ها و پالت‌ها |
| `GET /settings` | مدیر | مقدارهای فعلی + پالت نهایی |
| `POST /settings` | مدیر | `{"values":{...}}` ذخیره‌ی جزئی؛ کش افزونه‌های رایج پاک می‌شود |
| `POST /settings/reset` | مدیر | بازگشت به پیش‌فرض (نام سایت/لوگو دست‌نخورده) |
| `POST /preview` | مدیر | `{"values":{...},"path":"/"}` → آدرس پیش‌نمایش **ذخیره‌نشده** (۳۰ دقیقه اعتبار) |

لوگو و تصاویر را اپ با API خود وردپرس (`/wp/v2/media`) آپلود می‌کند و شناسه‌ی تصویر را ذخیره می‌کند.

## امنیت

- ورود فقط با Application Passwords (قابل ابطال، جدا از رمز اصلی)؛ تنظیمات ظاهر با `manage_options`، محصولات با `edit_products`.
- همه‌ی ورودی‌ها در سرور با `schema.json` پاک‌سازی می‌شوند؛ **هیچ CSS/HTML خامی** از اپ پذیرفته نمی‌شود. رنگ‌ها فقط hex معتبرند.
- توکن پیش‌نمایش تصادفی ۲۰ کاراکتری، موقت، فقط‌خواندنی، `noindex` و بدون کش.
- اپ CSP سخت‌گیر دارد (بدون اسکریپت/استایل بیرونی). رمز برنامه فقط در `localStorage` همان دستگاه است؛ هر وقت خواستید از پروفایل وردپرس ابطالش کنید.
- اگر قالب غیرفعال شود، API هم خاموش می‌شود.

## عیب‌یابی

| علامت | راه‌حل |
|---|---|
| «نام کاربری یا رمز درست نیست» ولی درست است | هاست هدر `Authorization` را حذف می‌کند. در `.htaccess` (قبل از بلوک وردپرس): `RewriteEngine On` ، `RewriteCond %{HTTP:Authorization} ^(.*)` ، `RewriteRule ^(.*) - [E=HTTP_AUTHORIZATION:%1]`. روی Nginx: `fastcgi_param HTTP_AUTHORIZATION $http_authorization;` |
| «رمزهای عبور برنامه» در پروفایل نیست | HTTPS فعال نیست، یا افزونه‌ی امنیتی آن را خاموش کرده |
| «قالب نسخه‌ی ۴ فعال نیست» | قالب بازار فعال نیست یا پیوند یکتا خراب است (اپ خودش `?rest_route=` را هم امتحان می‌کند) |
| پیش‌نمایش خالی | سایت/CDN فریم‌شدن را مسدود کرده (`X-Frame-Options`)؛ «باز کردن در تب جدید» را بزنید |
| تغییر ذخیره شد ولی سایت عوض نشد | کش CDN (مثل Cloudflare) را پاک کنید؛ افزونه‌های کش رایج خودکار پاک می‌شوند |

## ساخت فایل نصبی اندروید (APK) با گیت‌هاب

1. در ریپو: **Actions ← android ← Run workflow** (روی `main`). حدود ۸ تا ۱۵ دقیقه طول می‌کشد.
2. بعد از سبزشدن، وارد همان اجرا شوید و از بخش **Artifacts** فایل `sungold-admin-apk` را دانلود کنید. داخل zip فایل `sungold-admin.apk` است.
3. روی گوشی اندروید فایل را باز کنید و اجازه‌ی «نصب از منبع ناشناس» را بدهید.
4. اختیاری: تگ بزنید (`git tag v1.0.0 && git push --tags`) تا APK در بخش **Releases** هم بیاید و لینک مستقیم داشته باشید.

نکته‌ها:
- این APK با کلید debug امضا می‌شود؛ برای استفاده‌ی شخصی/تیمی کافی است. برای **Google Play** باید کلید امضای release ساخته و به workflow اضافه شود.
- **آیفون:** فایل نصبی رایگان ممکن نیست (حساب Apple Developer و Mac/امضا لازم است). راه رایگان: Safari ← Share ← Add to Home Screen (همان PWA).
- نام و شناسه‌ی اپ در `capacitor.config.json` و آیکن/اسپلش در پوشه‌ی `assets/` است.
- اگر ساخت قرمز شد، متن مرحله‌ی قرمز در Actions را برای رفع خطا بفرستید.

## وضعیت تست

- تست‌های اپ (۲۵ بررسی ظاهر/پیش‌نمایش + ۴۶ بررسی بنر/محصول/سئو + ۴۴ بررسی سفارشات با CSP فعال، موبایل و دسکتاپ)، ۲۸ بررسی استودیوی عکس شامل حالت «با کادر» روی عکس شلوغ (خروجی WebP با Pillow صحت‌سنجی می‌شود)، ۱۱ تست تحلیل سئو، ۱۲ تست حذف پس‌زمینه و الگوریتم رنگ: ✔ روی سرور آزمایشی.
- **ساخت APK در گیت‌هاب هنوز اجرا نشده** (اینجا اینترنت و Android SDK نبود)؛ فایل‌های آن بر پایه‌ی روش استاندارد Capacitor نوشته شده.
- **PHP با وردپرس واقعی هنوز اجرا نشده** (از جمله `inc/products.php` و ذخیره‌ی سئو در Rank Math/Yoast؛ سرور آزمایشی فقط رفتار را شبیه‌سازی می‌کند). CI در GitHub با `php -l` سینتکس را می‌سنجد؛ قبل از سایت اصلی، روی **staging** با `WP_DEBUG=true` امتحان کنید.
  ماژول‌های `inc/` طوری بارگذاری می‌شوند که خطای احتمالی آن‌ها سایت را سفید نکند (قالب با پیش‌فرض‌ها کار می‌کند).
